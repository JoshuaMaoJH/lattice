签名特性

图不是程序的示意图，它就是程序

节点的 ID 会作为注释留在生成的代码里。这不是装饰——它是「图 ↔ 代码」这条 对应关系可被机器验证的形式，也是将来做双向同步的锚点。 把鼠标放到任意一个节点上，看它变成了哪几行 Dart。

前后端只有一种语言

标记为服务端的子图编译成一个只依赖 dart:io 的程序，客户端拿到 类型化的调用桩。模型文件两边逐字节相同——「一个 Quote 是什么」只有一个定义。

客户端调用点
quote.value = await priceFor(sku.value, quantity.value);
服务端POST /rpc/priceFor
Quote priceFor(String sku, int quantity) =>    _buildQuote(sku, quantity, _unitPrice(sku), _discountRate(quantity));

序列化在生成的桩里，页面看不到它。真实往返已验证： {"result":{"sku":"PRO-1","total":529.2}}

还没做到的

这些是真的没做，不是没写

  • 服务端没有部署过。生成的是零依赖 Dart 程序，扔到装了 Dart 的主机上就能跑，但这一步没验证。
  • Windows 和 macOS 的打包只写了配置，没跑过——手上没有那两种宿主机。Linux 的 AppImage 与 .deb、Android 的 .apk 与 .aab、web 的 zip 都在真机上出过包。
  • 编辑器没有多选，所以折叠的成员是在属性面板里以逗号分隔的 ID 列表编辑的。
  • Prefab 不收 children 和回调。回调意味着组件要往外发事件，那需要先想清楚它的形状。
  • ForEach 模板里不能有自己的状态。每项一份的状态需要先解决身份问题，方案留了缝，还没做。
  • 图 ↔ 代码只有单向。反向同步的锚点（节点 ID 注释）已经在了，但没实现。
