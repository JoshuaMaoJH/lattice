# ADR-013：工程自己定义的节点是模板，不是代码

**状态**：已接受（R20）

## 背景

项目书把 R20 列为「架构预留」，理由是内置节点已经全部走同一份 schema 注册，
所以扩展点天然存在。真要做的时候，问题变成了：一个工程定义的节点，**它的身体
是什么**。

三个选项：

1. **动态加载 Dart**：工程提供一个包，编辑器加载它注册 schema 和 lowering。
   最灵活，但 Dart AOT 没有动态加载；编辑器要么改成 JIT，要么每加一个节点就得
   重新编译一次编辑器。
2. **节点即子图**：一个自定义节点就是一段图。这其实是 Prefab 和 Subgraph 已经
   在做的事，再做一遍不会多出表达力——它无法引入内置库里没有的**运算**。
3. **节点即模板**：JSON 声明引脚，加一段带 `{引脚名}` 占位符的 Dart 源码。

## 决定

选 3。`nodes/*.json`，两类：

- `compute` — 纯的，恰好一个输出，模板是**表达式**；
- `action` — 有副作用，没有数据输出，带 `exec`/`next`，模板是**语句**。

## 代价

**模板是被粘贴进页面的源码，不是被调用的函数。** 这意味着：

- 拼错了不会在定义处报错，会在生成的工程 `dart analyze` 时报错，指向生成的行。
  这是可接受的：生成代码本来就要过 analyze，而节点 ID 注释能把行号找回定义。
- 输入表达式被逐个加括号后再代入，整个模板外面再加一层。否则一个求和输入接进
  `{a} * 2` 会重新结合成 `1 + 2 * 2`。这条有测试锁着。

**不提供 `state` 和 `control` 两类。** state 会变成第二个可变状态来源，违反 §5
规则 2；control 要自己的 lowering，不是一次替换能表达的。这两类要扩展，得改
编译器，那是另一件事。

## 为什么不做成全局注册

`NodeRegistry.register` 是个静态方法，看起来像是给插件准备的。但编辑器要能开
不同工程，静态注册会串味。所以走的是 `NodeLookup(project)` ——和 `WidgetLookup`
处理 Prefab 完全一样的形状。内置的赢：撞名的定义被校验器拒绝，而不是悄悄覆盖
掉编译器自己的 lowering。

## 顺带修掉的

`extraImports` 一直被无条件拼上 `../`（页面在 `lib/pages/` 下，手写代码在
`lib/custom/`）。一个自定义节点要 `dart:math`，就会生成 `import '../dart:math'`。
Dart Code 节点其实早就能踩到这个洞，只是没人写过需要 `dart:` 的表达式。带
scheme 的 URI 现在原样通过。
